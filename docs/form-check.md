# フォーム測定（2026-09-26）

ダウンロードのきっかけになる機能として追加した。カメラで骨格を取り、
回数と到達点を測って記録する。

## 何を測るか

| 種目 | 測る値 | 判定 |
| --- | --- | --- |
| スクワット | 膝の角度 | 100度より深く曲げて160度まで伸ばしたら1回 |
| 蹴り | 足の高さ（腰を0、肩を1とした体幹比） | 0.3以上まで上げて下ろしたら1回。0未満=下段、1未満=中段、1以上=上段 |

どちらも左右それぞれの最高到達点を残し、1割以上ずれていれば
「左が◯%ぶん届いていません」と出す。本人が気づいていないことが多く、
測る値として意味がある。

## 型の採点をしない理由

型の評価軸（締め・極め・緩急・目付け）は単眼2Dの骨格点では見えない。
突きは正面から見ると腕が体に重なり、姿勢推定が最も苦手な条件になる。
外すと、いちばん必要な「実際に競技をやっている人」に低評価を付けられる。

測るのは「角度」と「高さ」だけにしてある。どちらも骨格点から一意に決まり、
間違えようがない。

## 作りの方針

判定はすべて `lib/features/form_check/pose_metrics.dart` と
`form_check_controller.dart` に置き、ML Kit の型に依存させていない。
シミュレータにはカメラが無く実機でしか動かせないため、判定部分だけでも
端末なしで検証できるようにしてある（テスト28件）。

カメラと ML Kit の繋ぎ込みは `pose_adapter.dart` と `form_check_screen.dart`
に薄く寄せてある。ここは実機で確認が必要。

| ファイル | 役割 | 端末なしで検証 |
| --- | --- | --- |
| `pose_metrics.dart` | 角度・高さ・回数・左右差の計算 | できる |
| `form_check_controller.dart` | 測定中の状態 | できる |
| `form_session.dart` | 記録の型と前回比較 | できる |
| `pose_adapter.dart` | ML Kit との変換 | できない |
| `form_check_screen.dart` | カメラ画面 | できない |

## シミュレータでは動かせない

ML Kit の pod は arm64 のシミュレータ用ビルドを持っていない。
Apple Silicon の Mac では、シミュレータ実行時に arm64 が除外される
（`flutter build ios --simulator` のログに警告が出る）。

実機ビルドと配布ビルドには影響しない。開発中に画面を見たい場合は
実機をつなぐこと。

## 実機で確かめること

1. カメラの許可を求めるダイアログが出るか
2. 全身が映ったときに「回数 / いま / ベスト」が出るか
3. スクワット10回で数字が10になるか（多くも少なくもならないか）
4. 前面カメラで左右が入れ替わっていないか
5. 記録が保存され、履歴に出るか

とくに4番は `pose_adapter.dart` の向き補正で、実機でしか確認できない。

## 付随して変わったこと

**iOS の最低動作環境が 13.0 → 15.5 に上がった。** ML Kit の要求。
iOS 13 が動く端末（iPhone 6s 以降）はすべて 15.5 も動くため、
対応端末は減らない。更新していない利用者だけが影響を受ける。

**アプリのサイズが大きく増える。** `flutter build ios --release` で実測した
ところ、Runner.app は 100MB。内訳は次のとおり。

| 中身 | サイズ |
| --- | --- |
| Runner 本体（ML Kit の静的ライブラリを含む） | 52MB |
| MLKitPoseDetectionAccurate のモデル | 9MB |
| MLKitPoseDetectionFast のモデル | 6MB |
| その他の MLKit リソース | 2MB |
| Frameworks 一式 | 33MB |

これは配信前の値で、App Store の実際のダウンロードサイズは端末ごとの
絞り込みと圧縮でこれより小さくなる。提出後に App Store Connect の
「App サイズ」で確認すること。

速い方のモデルだけで足りる場合、Accurate の 9MB は削れる余地があるが、
プラグインの podspec が両方を要求しているため、そのままでは外せない。

**映像は端末の外に出ない。** 骨格検出はオンデバイスで、保存するのは
回数と数値だけ。画像も動画も送信しないので、プライバシー表示に
「写真・ビデオ」を追加する必要はない。カメラの用途説明は Info.plist の
`NSCameraUsageDescription` に入れてある。

## 実機のデータで詰めるところ

しきい値は机上で決めた値なので、実際に測って調整する必要がある。

| 値 | いまの設定 | 場所 |
| --- | --- | --- |
| スクワットの下限 | 膝 100 度 | `FormCheckController._counterFor` |
| スクワットの復帰 | 膝 160 度 | 同上 |
| 蹴りの下限 | 体幹比 0.3 | 同上 |
| 蹴りの復帰 | 体幹比 -0.05 | 同上 |
| 骨格点の採用 | 確からしさ 0.5 | `PoseFrame.minLikelihood` |

記録は動作の最中（下がりきっている間）だけ更新する。構えている間や
測り終えたあとの姿勢を含めると、しゃがんで待っているだけで記録が
伸びてしまうため。

骨格点が一瞬だけ飛んだときの外れ値は、いまは弾いていない。実機で
どの程度ぶれるかを見てから、必要なら数フレームの平均を取る。

## 残っていること

- 骨格の線を画面に重ねて描く（いまは数字だけ）
- 測定結果の共有（「上段まで上がった」を画像で出す）
- 種目を増やす場合は `ExerciseKind` に足して、しきい値を
  `FormCheckController._counterFor` に書く
